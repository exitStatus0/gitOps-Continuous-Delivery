Оцінка знань з ArgoCD

Розділ 1: Основи ArgoCD (25 балів)

Питання 15 балів
Що таке ArgoCD?
Відповідь: B — ArgoCD спеціально розроблений як декларативний інструмент безперервної доставки на основі GitOps для Kubernetes. Це не платформа CI (A), реєстр контейнерів (C) чи інструмент моніторингу (D), хоча він інтегрується з цими компонентами.
Питання 25 балів
Який архітектурний шаблон використовує ArgoCD для управління кількома кластерами?
Відповідь: B — ArgoCD використовує архітектуру hub-and-spoke, де центральний кластер control-plane з ArgoCD управляє розгортаннями в кількох цільових кластерах. Цей централізований підхід надає єдину панель для управління всіма кластерами.
Питання 35 балів
У контексті GitOps, яку роль виконує ArgoCD?
Відповідь: B — ArgoCD є агентом автоматизації, який реалізує принципи GitOps. Він безперервно витягує бажаний стан з Git-репозиторіїв і узгоджує його з живим станом у кластерах Kubernetes, автоматично виявляючи та виправляючи дрейф.
Питання 45 балів
Так чи Ні: ArgoCD використовує модель розгортання на основі push, де конвеєри CI/CD проштовхують зміни безпосередньо в кластери.
Відповідь: B — ArgoCD використовує **модель pull**, що є фундаментальним для GitOps. ArgoCD витягує зміни з Git-репозиторіїв, а не отримує їх через push з конвеєрів CI/CD безпосередньо в кластери. Це покращує безпеку та слідує принципу GitOps "витягується автоматично".
Питання 55 балів
Як ArgoCD обробляє дрейф конфігурації?
Відповідь: C — Коли ArgoCD виявляє дрейф (різницю між бажаним станом у Git та живим станом у кластері), він автоматично або вручну (залежно від політики синхронізації) узгоджує живий стан відповідно до Git. Ця можливість самовідновлення є основною функцією ArgoCD.

Розділ 2: ArgoCD та GitOps (20 балів)

Питання 65 балів
Що означає "безперервне узгодження" в контексті ArgoCD?
Відповідь: C — Безперервне узгодження — це процес, коли ArgoCD постійно порівнює бажаний стан (визначений у Git) з живим станом (у кластері) та автоматично виправляє будь-які різниці. Це забезпечує, що кластер завжди залишається синхронізованим з Git.
Питання 75 балів
Який принцип GitOps підтримує ArgoCD, використовуючи Git як джерело правди?
Відповідь: B — Використовуючи Git як єдине джерело правди, ArgoCD підтримує принципи GitOps декларативної конфігурації (визначення того, що має існувати) з версійністю (історія Git) та незмінністю (коміти Git є незмінними). Це контрастує з імперативними підходами, які визначають, як досягти стану.
Питання 85 балів
Так чи Ні: ArgoCD вимагає зберігання облікових даних з правом запису до кластера Kubernetes у конвеєрі CI/CD.
Відповідь: B — Це ключова перевага безпеки ArgoCD! Оскільки ArgoCD працює всередині кластера та витягує з Git, конвеєру CI/CD не потрібен доступ на запис до кластера. Конвеєр CI потребує лише оновлювати Git, а ArgoCD обробляє розгортання. Це зменшує поверхню атаки та слідує принципу найменших привілеїв.
Питання 95 балів
Що відбувається, коли ArgoCD виявляє, що живий стан кластера відрізняється від бажаного стану в Git?
Відповідь: B — Коли виявлено дрейф, поведінка ArgoCD залежить від політики синхронізації. З увімкненою auto-sync він негайно узгоджує. З ручною синхронізацією він сповіщає користувачів, але чекає на ручне схвалення. У будь-якому випадку він може відновити бажаний стан з Git.

Розділ 3: ArgoCD та Continuous Delivery (20 балів)

Питання 105 балів
У робочому процесі CD з ArgoCD, що є основною відповідальністю ArgoCD?
Відповідь: C — У робочому процесі CD ArgoCD зосереджується саме на фазі розгортання — беручи зібрані, протестовані додатки та розгортаючи їх у Kubernetes. Конвеєр CI обробляє збірку (A) та тестування (B), а Git обробляє управління вихідним кодом (D).
Питання 115 балів
Як конвеєр CI зазвичай взаємодіє з ArgoCD у робочому процесі GitOps?
Відповідь: B — У правильному робочому процесі GitOps конвеєр CI не взаємодіє безпосередньо з кластером або ArgoCD. Натомість він оновлює маніфести Kubernetes (зазвичай з новими тегами образів) у Git-репозиторії, а ArgoCD автоматично виявляє ці зміни та розгортає їх. Це розділення обов'язків є ключовим для GitOps.
Питання 125 балів
Так чи Ні: ArgoCD обробляє як CI (Continuous Integration), так і CD (Continuous Delivery) фази конвеєра доставки програмного забезпечення.
Відповідь: B — ArgoCD зосереджується лише на фазі CD (Continuous Delivery/Deployment). Він не збирає код, не запускає тести та не створює образи контейнерів — це робота інструментів CI, таких як Jenkins, GitLab CI або GitHub Actions. ArgoCD бере артефакти з CI та розгортає їх у Kubernetes.
Питання 135 балів
Яка ключова перевага використання ArgoCD для фази розгортання CD?
Відповідь: C — ArgoCD дозволяє декларативні розгортання, де ви визначаєте бажаний стан, а не пишете скрипти розгортання. Оскільки все в Git, ви отримуєте повну історію аудиту того, хто що розгортав і коли, плюс легкі можливості відкату за допомогою `git revert`. Він не покращує компіляцію (A), огляд коду (B) чи продуктивність ноутбука (D).

Розділ 4: ArgoCD та Kubernetes (20 балів)

Питання 145 балів
Як визначаються додатки ArgoCD у Kubernetes?
Відповідь: B — ArgoCD використовує Kubernetes CRD для визначення додатків. Це робить ArgoCD Kubernetes-native, дозволяючи адміністраторам використовувати знайомі інструменти, такі як `kubectl` та YAML, для управління додатками ArgoCD так само, як і будь-яким іншим ресурсом Kubernetes.
Питання 155 балів
Які інструменти управління конфігурацією підтримує ArgoCD? (Виберіть НАЙПОВНІШУ відповідь)
Відповідь: C — ArgoCD є гнучким і підтримує кілька інструментів управління конфігурацією: звичайні YAML маніфести, Helm charts, Kustomize, Jsonnet та навіть користувацькі плагіни управління конфігурацією. Ця гнучкість дозволяє командам використовувати їхні улюблені інструменти.
Питання 165 балів
Так чи Ні: Конфігурації ArgoCD є портативними між кластерами Kubernetes незалежно від базової інфраструктури.
Відповідь: A — Оскільки ArgoCD використовує Kubernetes-native CRD та стандартні маніфести Kubernetes, конфігурації є портативними для будь-якого кластера Kubernetes — чи то він працює на AWS, GCP, Azure, on-premises, чи навіть у локальних кластерах розробки, таких як kind або minikube.
Питання 175 балів
Що дозволяє конфігурація ArgoCD `syncPolicy: automated: {}`?
Відповідь: B — Встановлення `syncPolicy: automated: {}` дозволяє auto-sync, що означає, що ArgoCD автоматично розгортатиме зміни з Git у кластер без ручного втручання. Це не контролює масштабування кластера (C) або резервне копіювання (D), і це саме усуває потребу в ручному схваленні (A).

Розділ 5: Функції ArgoCD та найкращі практики (15 балів)

Питання 185 балів
Що дозволяє робити веб-інтерфейс ArgoCD?
Відповідь: B — Веб-інтерфейс ArgoCD є потужним інструментом для візуалізації ресурсів Kubernetes та їх взаємозв'язків, управління життєвим циклом додатків, перегляду статусу синхронізації, перевірки статусу здоров'я, доступу до логів та тригерування ручних синхронізацій. Він не надає редагування коду (A), створення Git-репозиторіїв (C) чи інструментів проектування архітектури (D).
Питання 195 балів
Так чи Ні: У робочому процесі GitOps з ArgoCD рекомендується зберігати вихідний код додатку та маніфести конфігурації Kubernetes в одному репозиторії.
Відповідь: B — Найкраща практика — **розділяти** вихідний код додатку та маніфести конфігурації Kubernetes в різні репозиторії. Це слідує принципу GitOps розділення обов'язків, забезпечує кращу безпеку (розробникам не потрібен доступ до production конфігурацій) та дозволяє незалежне версіонування та контроль доступу.
Питання 205 балів
Що таке шаблон "App of Apps" в ArgoCD?
Відповідь: B — Шаблон "App of Apps" використовує один додаток ArgoCD, який вказує на директорію, що містить визначення для кількох інших додатків. Цей батьківський додаток управляє дочірніми додатками, що полегшує розгортання цілих середовищ або пов'язаних наборів додатків як єдиної одиниці.
