Section 1: Continuous Delivery Fundamentals (10 pts)

Question 15 pts
What is the primary goal of Continuous Delivery?
Answer: C — Continuous Delivery focuses on automating the release process to get changes into production safely, quickly, and sustainably. It doesn’t necessarily eliminate human involvement (that’s Continuous Deployment) or reduce headcount—it frees engineers from toil to focus on value delivery.
Question 25 pts
What is the relationship between Continuous Integration (CI) and Continuous Delivery (CD)?
Answer: C — CI is an essential prerequisite for CD. You need to first integrate and test code changes (CI) before you can reliably deliver them (CD). CI focuses on merging and testing code, while CD automates deployment to environments.

Section 2: GitOps Principles (15 pts)

Question 35 pts
Which of the following is NOT one of the four GitOps principles?
Answer: C — The four GitOps principles are: Declarative, Versioned and Immutable, Pulled Automatically (not pushed), and Continuously Reconciled. The pull-based model is a key differentiator from traditional push-based deployments.
Question 45 pts
What is the main security advantage of the GitOps pull model over the traditional push model?
Answer: B — In the pull model, a GitOps operator running inside the cluster pulls changes from Git. This means the CI/CD system doesn’t need credentials with write access to the cluster’s API, significantly reducing the attack surface if the CI/CD system is compromised.
Question 55 pts
What happens when drift is detected in a GitOps setup with self-healing enabled?
Answer: B — With self-healing enabled, the GitOps operator automatically reconciles the cluster state to match the desired state defined in Git. Manual changes to the cluster are automatically reverted.

Section 3: ArgoCD Architecture and Features (15 pts)

Question 65 pts
What deployment model does ArgoCD use for managing multiple clusters?
Answer: C — ArgoCD uses a hub-and-spoke model where a central control plane cluster (with ArgoCD installed) manages deployments to multiple target clusters. This enables centralized management while maintaining scalability.
Question 75 pts
Which of the following is ArgoCD responsible for in a CI/CD pipeline?
Answer: C — ArgoCD focuses on the deployment phase of Continuous Delivery. It’s responsible for deploying applications to Kubernetes by syncing the desired state from Git. Building, testing, and scanning are handled by CI tools.
Question 85 pts
What does the selfHeal: true setting in an ArgoCD Application’s sync policy do?
Answer: C — When selfHeal: true is enabled, ArgoCD automatically reverts any manual changes made directly to the cluster to match the desired state in Git. This prevents configuration drift.

Section 4: ArgoCD Application CRD (15 pts)

Question 95 pts
In an ArgoCD Application manifest, what does the spec.source field define?
Answer: B — The spec.source field defines where ArgoCD should get the application manifests from, including the repository URL, path within the repo, target revision (branch/tag/commit), and config management tool settings.
Question 105 pts
What config management tool will ArgoCD detect if it finds a Chart.yaml file in the source path?
Answer: D — ArgoCD automatically detects the config management tool based on files in the source path. A Chart.yaml file indicates a Helm chart. Similarly, kustomization.yaml indicates Kustomize.
Question 115 pts
Which sync option should you use to automatically create the target namespace if it doesn’t exist?
Answer: B — The CreateNamespace=true sync option tells ArgoCD to automatically create the destination namespace if it doesn’t already exist before deploying resources.

Section 5: GitOps Prerequisites and Best Practices (20 pts)

Question 125 pts
Why is automated testing CRITICAL for GitOps success?
Answer: C — In GitOps with auto-sync, deployments are automated. If your tests don’t catch bugs, those bugs deploy automatically too. There’s no human safety net in a fully automated pipeline, making comprehensive testing essential.
Question 135 pts
What should you NEVER store in a Git repository, even in a private one?
Answer: C — Never store plain-text secrets in Git. Even private repositories can be compromised, and Git history is permanent. Use secret management solutions like Sealed Secrets, External Secrets Operator, or HashiCorp Vault instead.
Question 145 pts
What is the purpose of branch protection rules in a GitOps workflow?
Answer: B — In GitOps, merging to the main branch effectively means deploying to production. Branch protection rules ensure all changes go through proper review (PRs, CI checks, approvals) before being deployed.
Question 155 pts
Which environment should typically have auto-sync enabled?
Answer: B — Best practice is to enable auto-sync for non-production environments (dev, QA) to enable fast iteration, while keeping production with manual sync for additional control and approval gates.

Section 6: The App of Apps Pattern (10 pts)

Question 165 pts
What is the main benefit of the App of Apps pattern?
Answer: B — The App of Apps pattern allows you to manage ArgoCD Application resources declaratively through GitOps, just like any other Kubernetes resource. Instead of manually creating Applications through the UI, you define them in Git.
Question 175 pts
Where does the App of Apps Application typically point to?
Answer: B — The App of Apps Application points to a folder in your Git repository that contains other ArgoCD Application manifests. When synced, it creates/manages all the child Applications defined in that folder.

Section 7: Troubleshooting and Operations (15 pts)

Question 185 pts
An Application shows “Synced” but “Degraded” health status. What does this mean?
Answer: B — “Synced” means the manifests from Git were successfully applied to the cluster. “Degraded” means the resources themselves are failing (e.g., pods can’t start due to invalid image tag, resource limits, or configuration errors).
Question 195 pts
What is the simplest way to rollback a deployment in GitOps?
Answer: C — In GitOps, rollback is as simple as reverting the Git commit that caused the problem. ArgoCD will automatically sync the reverted state to the cluster.
Question 205 pts
What is the primary purpose of monitoring in a GitOps environment?
Answer: B — With automated deployments, you need automated detection of problems. Monitoring helps you quickly identify when a deployment causes issues, enabling rapid response and rollback if needed.

Section 8: Comprehensive Scenarios (15 pts)

Question 215 pts
Your team is implementing GitOps for the first time. What should be your first step?
Answer: B — When starting with GitOps, begin with non-production environments and manual sync. This allows you to learn the workflow, build confidence, and identify issues before applying automation to critical systems.
Question 225 pts
A developer manually changed a ConfigMap in production to fix an urgent issue. With GitOps and self-heal enabled, what happens next?
Answer: B — With self-heal enabled, ArgoCD continuously reconciles the cluster state with Git. The manual change will be automatically reverted to match the desired state in Git. To make the change permanent, it must be committed to Git.
Question 235 pts
Your organization wants to implement GitOps but currently has no automated testing. What should you do?
Answer: C — Automated testing is a critical prerequisite for GitOps success. Without comprehensive tests, enabling auto-sync means bugs automatically deploy to production. Invest in testing before enabling automation.
