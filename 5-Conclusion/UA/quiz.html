Фінальна перевірка знань: Опанування GitOps та ArgoCD

Розділ 1: Основи Continuous Delivery (10 балів)

Питання 15 балів
Яка основна мета Continuous Delivery?
Відповідь: C — Continuous Delivery фокусується на автоматизації процесу релізу для безпечної, швидкої та стійкої доставки змін у production. Він не обов'язково усуває людське втручання (це Continuous Deployment) та не скорочує персонал — він звільняє інженерів від рутини для фокусування на створенні цінності.
Питання 25 балів
Який зв'язок між Continuous Integration (CI) та Continuous Delivery (CD)?
Відповідь: C — CI є необхідною передумовою для CD. Спочатку потрібно інтегрувати та протестувати зміни коду (CI), перш ніж надійно доставляти їх (CD). CI фокусується на злитті та тестуванні коду, тоді як CD автоматизує розгортання в середовища.

Розділ 2: Принципи GitOps (15 балів)

Питання 35 балів
Що з наведеного НЕ є одним з чотирьох принципів GitOps?
Відповідь: C — Чотири принципи GitOps: Декларативний, Версіонований та незмінний, Автоматично витягується (Pull, а не Push) та Безперервно узгоджується. Модель на основі витягування є ключовою відмінністю від традиційних push-базованих розгортань.
Питання 45 балів
Яка основна перевага безпеки моделі GitOps pull над традиційною моделлю push?
Відповідь: B — У моделі pull GitOps-оператор, що працює всередині кластера, витягує зміни з Git. Це означає, що CI/CD системі не потрібні облікові дані з правами на запис до API кластера, що значно зменшує поверхню атаки, якщо CI/CD система буде скомпрометована.
Питання 55 балів
Що відбувається, коли виявлено відхилення (drift) у налаштуванні GitOps з увімкненим самовідновленням?
Відповідь: B — З увімкненим самовідновленням GitOps-оператор автоматично узгоджує стан кластера відповідно до бажаного стану, визначеного в Git. Ручні зміни в кластері автоматично скасовуються.

Розділ 3: Архітектура та функції ArgoCD (15 балів)

Питання 65 балів
Яку модель розгортання використовує ArgoCD для управління кількома кластерами?
Відповідь: C — ArgoCD використовує модель hub-and-spoke, де центральний control-plane кластер (з встановленим ArgoCD) керує розгортаннями на кількох цільових кластерах. Це забезпечує централізоване управління з підтримкою масштабованості.
Питання 75 балів
За що відповідає ArgoCD у CI/CD конвеєрі?
Відповідь: C — ArgoCD фокусується на фазі розгортання Continuous Delivery. Він відповідає за розгортання додатків у Kubernetes шляхом синхронізації бажаного стану з Git. Збірка, тестування та сканування виконуються CI-інструментами.
Питання 85 балів
Що робить налаштування selfHeal: true у політиці синхронізації ArgoCD Application?
Відповідь: C — Коли увімкнено selfHeal: true, ArgoCD автоматично скасовує будь-які ручні зміни, зроблені безпосередньо в кластері, щоб відповідати бажаному стану в Git. Це запобігає дрейфу конфігурації.

Розділ 4: ArgoCD Application CRD (15 балів)

Питання 95 балів
У маніфесті ArgoCD Application, що визначає поле spec.source?
Відповідь: B — Поле spec.source визначає, звідки ArgoCD має отримувати маніфести додатку, включаючи URL репозиторію, шлях у репо, цільову ревізію (branch/tag/commit) та налаштування інструменту управління конфігурацією.
Питання 105 балів
Який інструмент управління конфігурацією виявить ArgoCD, якщо знайде файл Chart.yaml у вихідному шляху?
Відповідь: D — ArgoCD автоматично виявляє інструмент управління конфігурацією на основі файлів у вихідному шляху. Файл Chart.yaml вказує на Helm chart. Аналогічно, kustomization.yaml вказує на Kustomize.
Питання 115 балів
Яку опцію синхронізації слід використовувати для автоматичного створення цільового namespace, якщо він не існує?
Відповідь: B — Опція синхронізації CreateNamespace=true вказує ArgoCD автоматично створювати цільовий namespace, якщо він ще не існує, перед розгортанням ресурсів.

Розділ 5: Передумови та найкращі практики GitOps (20 балів)

Питання 125 балів
Чому автоматизоване тестування є КРИТИЧНИМ для успіху GitOps?
Відповідь: C — У GitOps з auto-sync розгортання автоматизовані. Якщо ваші тести не виловлюють баги, ці баги розгортаються автоматично теж. У повністю автоматизованому конвеєрі немає людського запобіжника, що робить комплексне тестування необхідним.
Питання 135 балів
Що ви НІКОЛИ не повинні зберігати в Git-репозиторії, навіть приватному?
Відповідь: C — Ніколи не зберігайте відкриті секрети в Git. Навіть приватні репозиторії можуть бути скомпрометовані, а історія Git є постійною. Натомість використовуйте рішення для управління секретами, такі як Sealed Secrets, External Secrets Operator або HashiCorp Vault.
Питання 145 балів
Яке призначення правил захисту гілок у робочому процесі GitOps?
Відповідь: B — У GitOps злиття в main гілку фактично означає розгортання в production. Правила захисту гілок забезпечують, що всі зміни проходять належну перевірку (PR, CI перевірки, схвалення) перед розгортанням.
Питання 155 балів
У якому середовищі зазвичай має бути увімкнено auto-sync?
Відповідь: B — Найкращою практикою є увімкнення auto-sync для non-production середовищ (dev, QA) для швидкої ітерації, зберігаючи production з ручною синхронізацією для додаткового контролю та затворів схвалення.

Розділ 6: Шаблон App of Apps (10 балів)

Питання 165 балів
Яка основна перевага шаблону App of Apps?
Відповідь: B — Шаблон App of Apps дозволяє декларативно керувати ресурсами ArgoCD Application через GitOps, як і будь-яким іншим ресурсом Kubernetes. Замість ручного створення Applications через UI, ви визначаєте їх у Git.
Питання 175 балів
Куди зазвичай вказує Application App of Apps?
Відповідь: B — Application App of Apps вказує на папку у вашому Git-репозиторії, яка містить інші маніфести ArgoCD Application. При синхронізації вона створює/керує всіма дочірніми Applications, визначеними в цій папці.

Розділ 7: Усунення несправностей та операції (15 балів)

Питання 185 балів
Application показує статус "Synced", але статус здоров'я "Degraded". Що це означає?
Відповідь: B — "Synced" означає, що маніфести з Git були успішно застосовані до кластера. "Degraded" означає, що самі ресурси виходять з ладу (наприклад, pods не можуть запуститися через невалідний image tag, обмеження ресурсів або помилки конфігурації).
Питання 195 балів
Який найпростіший спосіб відкотити розгортання в GitOps?
Відповідь: C — У GitOps відкат такий же простий, як скасування Git-коміту, що спричинив проблему. ArgoCD автоматично синхронізує скасований стан до кластера.
Питання 205 балів
Яке основне призначення моніторингу в середовищі GitOps?
Відповідь: B — З автоматизованими розгортаннями вам потрібне автоматичне виявлення проблем. Моніторинг допомагає швидко ідентифікувати, коли розгортання викликає проблеми, забезпечуючи швидке реагування та відкат за потреби.

Розділ 8: Комплексні сценарії (15 балів)

Питання 215 балів
Ваша команда вперше впроваджує GitOps. Яким має бути ваш перший крок?
Відповідь: B — При початку роботи з GitOps починайте з non-production середовищ та ручної синхронізації. Це дозволяє вивчити робочий процес, набути впевненості та виявити проблеми до застосування автоматизації до критичних систем.
Питання 225 балів
Розробник вручну змінив ConfigMap у production, щоб виправити термінову проблему. З GitOps та увімкненим самовідновленням, що відбудеться далі?
Відповідь: B — З увімкненим самовідновленням ArgoCD безперервно узгоджує стан кластера з Git. Ручна зміна буде автоматично скасована відповідно до бажаного стану в Git. Щоб зробити зміну постійною, її потрібно закомітити в Git.
Питання 235 балів
Ваша організація хоче впровадити GitOps, але наразі не має автоматизованого тестування. Що вам робити?
Відповідь: C — Автоматизоване тестування є критичною передумовою для успіху GitOps. Без комплексних тестів увімкнення auto-sync означає, що баги автоматично розгортаються в production. Інвестуйте в тестування перед увімкненням автоматизації.
