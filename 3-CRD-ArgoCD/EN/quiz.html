ArgoCD Application CRD Quiz

20 questions · 100 points · Test your understanding of Application CRDs

Section 1: Application CRD Fundamentals (25 pts)

Question 15 pts
What is an ArgoCD Application CRD?
Answer: B — An ArgoCD Application is a Kubernetes Custom Resource (CR) that contains all the information ArgoCD needs to deploy and manage an application.
Question 25 pts
Which field in the Application CRD is mandatory and defines where the manifests are sourced from?
Answer: C — The spec.source field is mandatory and defines where ArgoCD should get the manifests from (Git repository, Helm repository, etc.).
Question 35 pts
True or False: The Application CRD can only deploy plain YAML manifests.
Answer: False — ArgoCD Applications support Helm, Kustomize, Jsonnet, plain YAML/JSON, and custom plugins.
Question 45 pts
How does ArgoCD track resources deployed by an Application?
Answer: B — ArgoCD adds labels or annotations to all deployed resources. This allows it to monitor health, detect drift, perform cleanup, and show relationships in the UI.
Question 55 pts
Which of the following is NOT a supported config management tool in ArgoCD Applications?
Answer: C — ArgoCD natively supports Helm, Kustomize, Jsonnet, and plain YAML, but not Terraform. Terraform could be integrated via a custom Config Management Plugin.

Section 2: Source Configuration (20 pts)

Question 65 pts
In the source field, what does the targetRevision specify?
Answer: B — targetRevision specifies which version of the source to use: a branch name, tag, or specific commit SHA for Git repos, or chart version for Helm repos.
Question 75 pts
True or False: ArgoCD can automatically detect which config management tool to use based on the files in the repository.
Answer: True — ArgoCD performs automatic tool detection: Chart.yaml → Helm, kustomization.yaml → Kustomize, *.jsonnet → Jsonnet, otherwise plain YAML.
Question 85 pts
If a repository contains a Chart.yaml file, which tool will ArgoCD automatically detect?
Answer: C — Chart.yaml is the standard indicator of a Helm chart. ArgoCD will automatically detect this and use Helm to render manifests.
Question 95 pts
What is the purpose of specifying valueFiles in the Helm source configuration?
Answer: B — valueFiles specifies which values files to use when rendering the chart, enabling different configurations per environment (e.g., values-production.yaml).

Section 3: Destination Configuration (15 pts)

Question 105 pts
How can you specify the target cluster in the destination field?
Answer: C — ArgoCD lets you specify the target cluster by name (e.g., name: 'production') or by server URL (e.g., server: 'https://...').
Question 115 pts
What server URL should be used to deploy to the same cluster where ArgoCD is running?
Answer: B — https://kubernetes.default.svc is the standard in-cluster Kubernetes API server address for deploying to the same cluster where ArgoCD runs.
Question 125 pts
True or False: Cluster-scoped resources like ClusterRoles ignore the namespace specified in the destination field.
Answer: True — Cluster-scoped resources exist at the cluster level and are not confined to a namespace. Only namespace-scoped resources (Deployments, Services, etc.) use the destination namespace.

Section 4: Sync Policies and Behavior (25 pts)

Question 135 pts
What does it mean to “sync” an Application?
Answer: B — Syncing means reconciling the actual state in the cluster with the desired state defined in Git — fetching manifests, comparing, and applying changes.
Question 145 pts
Which sync policy configuration enables automatic synchronization when changes are detected in Git?
Answer: B — Setting syncPolicy.automated: {} enables auto-sync. There is no manual, scheduled, or continuous sync policy type in ArgoCD.
Question 155 pts
What does the selfHeal: true option do?
Answer: B — selfHeal: true enables automatic drift correction. If someone manually changes a resource via kubectl, ArgoCD will detect the drift and revert it to match Git.
Question 165 pts
True or False: The prune: true option will automatically delete resources from the cluster when they are removed from Git.
Answer: True — When prune: true is set, ArgoCD automatically deletes resources from the cluster when they are removed from the Git repository.
Question 175 pts
What does the CreateNamespace=true sync option do?
Answer: B — CreateNamespace=true automatically creates the destination namespace in the target cluster if it doesn’t already exist.

Section 5: Application Lifecycle and States (15 pts)

Question 185 pts
What does the “OutOfSync” status mean?
Answer: B — “OutOfSync” means the live state of resources in the cluster doesn’t match the desired state defined in Git.
Question 195 pts
Which health status indicates that all resources are running properly?
Answer: C — “Healthy” indicates all resources are running properly. “Synced” is a sync status, “Progressing” means resources are being updated, and “Active” is not a valid ArgoCD health status.
Question 205 pts
True or False: An Application can be “Synced” but still be “Degraded” in health status.
Answer: True — Sync status and health status are independent. A Deployment with a broken container image will be “Synced” (matches Git) but “Degraded” (pods in CrashLoopBackOff).
